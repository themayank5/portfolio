Case Study · 01

Design System that Scale

Designing the system behind scalable products—replacing inconsistent one-off decisions with shared rules, semantic tokens, and reusable components that scale across enterprise SaaS experiences.

Role:- UI/UX Designer Focus:- Design Systems for Enterprise SaaS Tool:- Figma
01 — The Problem

The problems I uncovered

As enterprise SaaS products grow, visual inconsistency rarely comes from one major mistake. It accumulates through hundreds of small decisions.

Seven Core Problems

→
Inconsistent UI patterns across different product areas making the experience feel fragmented
→
Repeated design decisions — the same problems solved differently each time by different teams
→
No shared design language between designers and developers
→
Typography and spacing applied arbitrarily, not systematically
→
Color usage without semantic meaning or consistent application
→
Components built from scratch each sprint rather than reused from a shared library
→
No scalable foundation — every new feature required rediscovering basic design rules

Individually, these decisions may seem insignificant. At scale, they create a product that becomes increasingly difficult to maintain and evolve

02 — The Reframe

From screens to rules

The most important shift in this project wasn't a design decision — it was a problem framing decision.

Instead of asking:

"How should this screen look?"

I reframed the problem as:

"What rules should determine how future screens are designed?"

That shift — from designing individual screens to designing the rules screens follow — became the foundation of the entire system.

03 — My Approach

How I Approached the System

Understand
Audited recurring visual and structural patterns across the product to identify where teams were solving the same problems differently.
Define
Established principles for hierarchy, meaning, spacing, structure, shape, and interaction—the underlying logic behind every visual decision.
Systemize
Translated those decisions into reusable foundations, semantic tokens, and components with clear relationships and states.
Apply
Applied the system to real product workflows and realistic information density, validating that the rules worked across different scenarios and screen sizes.

The system was approached as a hierarchy of decisions rather than a collection of isolated UI assets—each layer building on the one before it.

04 — System Architecture

Three Layers of Decision

The system is structured across three layers — each layer building on the one below it, so that every product decision traces back to a shared foundation.

Layer 1 — Foundation
Raw design values and primitives
Color · Typography · Spacing · Sizing · Radius · Grid · Elevation · Borders · Opacity · Breakpoints
↓
Layer 2 — Semantic
Meaning and product intent
Text · Surface · Border · Icon · Action · Feedback · Selection · Focus · Data Visualisation
↓
Layer 3 — Component
Reusable UI patterns and states
Button · Input · Checkbox · Radio · Badge · Tooltip · Tabs · Modal · Card · Search · Pagination
↓
Product UI
Real workflows built from the system
Navigation · Layouts · Workflows · States · Feedback · Responsive experiences
05 — BUILDING THE SYSTEM

From foundations to product

I translated the system from raw design values into semantic meaning, reusable components, and real product experiences. Each layer added context while keeping the underlying decisions consistent and reusable.

06 — Guiding Principles

The rules behind the Design System

Four principles guided every decision in the system — not rules about what things should look like, but rules about how to make those decisions.

Consistency
Repeated decisions should produce predictable outcomes. The same context should always lead to the same design behavior.
Meaning
Tokens should communicate product intent, not simply store values. Every semantic token should explain why it exists, not just what it contains.
Flexibility
The system should provide constraints without forcing every interface into the same composition. Rules should guide, not restrict.
Scalability
New product experiences should reuse the same foundations instead of recreating the visual language from scratch.
07 — Impact

What the system achieved

01 — Faster product delivery

Reduced product delivery time by 25% through reusable foundations, semantic tokens, and shared components.

02 — Shared design language

Established consistent UI patterns across enterprise SaaS experiences and reduced repeated design decisions.

03 — Stronger design–development collaboration

Created a shared system that helped designers and developers work from the same rules and reusable patterns across a 50+ member cross-functional team.

04 — Accessibility built into the system

Applied WCAG 2.1 AA principles across foundational and component-level decisions.
